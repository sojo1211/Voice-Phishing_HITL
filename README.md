# Voice-Phishing_HITL (GUARDION)

보이스피싱 피해 예방을 위한 HITL(Human-in-the-Loop) 기반 ESG 서비스

---

## 🌐 프로젝트 개요

‘가디온(GUARDION)’은 **보이스피싱 과정의 핵심 단계인 ‘고립’을 차단**하여
피해를 사전에 막는 것을 목표로 하는 **AI 기반 보이스피싱 실시간 탐지·알림 서비스**입니다.

* 대상: **50대 이상 시니어 금융 취약 계층**
* 방식: **통화 내용 분석 + GNN 기반 위험 탐지 + 보호자/지자체 연동 알림**
* 가치: **보이스피싱 피해 예방 + 2차 가해/가담 방지 + ESG(Social) 기여**

---
본 프로젝트에서 저는 **IT·AI 기술 총괄 역할**을 맡아,
서비스 전체의 **AI 구조 설계, HITL(Human-in-the-Loop) 방식 도입, 데이터 파이프라인 구성, GNN 모델 구조 정의, 보호자 연동 시스템 설계, 서버 중심 하이브리드 아키텍처 구성** 등의 핵심 기술 요소를 담당하였습니다.

### **1) AI 모델 및 HITL 구조 설계**

* 기존 탐지 앱의 Batch 학습(GNN) 한계를 분석하고
  → **Human-in-the-Loop 기반 실시간 그래프 보정 구조**를 적용
* 시니어의 억양/사투리 대응을 위해 **음향·언어 모델 파이프라인 구성**
* GNN 위험 탐지 점수 산출 로직 개발 및 최적화

### **2) 데이터 파이프라인·서버 구조 설계**

* 통화 음성 → 텍스트(STT) → GNN 입력 구조로 가공되는 흐름을 기획
* 개인정보 가명화 + Opt-in 기반 데이터 수집 프로세스 설계
* 서버 중심 하이브리드 구조로 실시간 탐지 가능하도록 설계
* AI·서버 간 피드백 루프 구현(피해자/보호자/HITL 데이터 → 그래프 보정)

### **3) 보호자 알림 시스템 & 실시간 대응 구조 설계**

* 위험 탐지 시
  → 피해자 스마트폰(진동·경고)
  → 보호자 긴급 문자
  → 지자체 연동 기능
  이 흐름의 전체 시스템 아키텍처 구성
* 통화 종료 후 TTS 안내 로직 설계

### **4) 기술 비교 분석 & 경쟁사 기술 구조 리서치**

* 후후·익시오 등 기존 서비스들의 GNN 구조 비교 및 한계 분석
* GNN vs HITL-GNN 성능 차이를 수치(AUC·재현율 8~9% 개선)로 증명하는 자료 제작

### **5) 서비스 전체 기술 도식화(플로우차트, 구조도, 데이터 처리 흐름)**

* 데이터 수집 → 가공 → GNN 분석 → HITL 보정 → 실시간 알림까지
  전체 기술 구조도를 제작하고 발표 구조로 재정리
* 기술적 기대효과(성능 향상, GPU 비용 절감, 실시간 학습 가능성) 도출

## 1️⃣ 문제 정의 – 왜 시니어인가?

<img width="1051" height="712" src="https://github.com/user-attachments/assets/9f1277a4-0b25-4a43-94a7-d6fa3408cb12" />

* 경찰청 자료에 따르면, 보이스피싱 피해액은 전년 동기(1~7월) 대비 **약 98.7% 증가**
* 특히 **50대 이상이 전체 피해자의 약 53%**를 차지하는 집중 타깃 계층
* 시니어층은

  * 전화·비대면 금융 환경에 빠르게 편입되었지만
  * 디지털 이해도·보안 대응 역량이 충분히 따라가지 못하는 세대

<img width="1073" height="723" src="https://github.com/user-attachments/assets/5fd3f5d0-be4c-460a-9e6e-f38a3adbf562" />

보이스피싱 수법은

* 명의 도용·카드 배송 사칭
* 공공기관 사칭 후 계좌 문제 주장
* 자녀 납치 협박 등
  점점 더 정교해지고 있으며, **정신적·물리적 고립 유도**를 핵심 도구로 사용합니다.

## 2️⃣ 범죄 구조 분석 – ‘고립’ 단계가 핵심

<img width="1048" height="718" src="https://github.com/user-attachments/assets/08a5e807-6e2a-4681-81e7-788b9b83f8e6" />

보이스피싱 범죄는 크게 세 단계로 진행됩니다.

1. **접촉(Contact)** – 전화·문자·메신저로 접근
2. **고립(Isolation)** –

   * “이 내용 유출 시 처벌 받는다”는 협박
   * “녹취를 위해 조용한 곳으로 가라”는 지시
     → 외부와의 소통 차단
3. **피해(Damage)** – 금전 이체, 개인정보 유출, 불법 가담, 2차 피해 발생

고립된 피해자는

* 이성적 판단이 떨어지고
* 범죄자의 비합리적 지시를 그대로 따르게 되며
* **피해자 → 2차 가해자(대포통장, 중개인)로 전환**되는 최악의 상황까지 이어질 수 있습니다.

> 👉 따라서 저희는 **‘고립 단계’를 끊어내는 것**을 보이스피싱 방지의 핵심으로 정의했습니다.

## 3️⃣ 서비스 콘셉트 – 고립을 깨는 ‘가디온(GUARDION)’

<img width="1021" height="725" src="https://github.com/user-attachments/assets/8ae7bdf4-8b42-44ad-a0c5-26bbb4d49c9b" />

* 보이스피싱은 **접촉 → 고립 → 피해** 순서로 발생
* 가디온은 이 흐름 중 **‘고립 단계’를 실시간으로 붕괴시키는 서비스**

### 핵심 메커니즘

1. **AI가 통화 중 위험 신호를 탐지**
2. **피해자 스마트폰에 실시간 경고(문구 + 진동)**
3. **보호자에게 동시에 긴급 문자 알림 전송**
4. 보호자 또는 지자체가 개입해 **피해자를 고립 상태에서 끌어냄**

<img width="1064" height="728" src="https://github.com/user-attachments/assets/80ce8209-fc78-486d-9b65-2a1da0e4630c" />

보호자가 없는 경우
→ 지자체·공공기관과의 연계를 통해 **지역 단위의 안전망**으로 확장 가능하며,
서비스 이름인 **‘가디온(GUARDION)’**은

> Guardian(보호자) + On(켜다) = “보호 모드가 켜지는 서비스”
> 라는 의미를 담고 있습니다.

## 4️⃣ 기술 구조 – HITL + GNN 기반 탐지 엔진

### 4-1. 기존 서비스 한계 (후후, 익시온 등)

<img width="1026" height="723" src="https://github.com/user-attachments/assets/013b25f9-5bf8-4022-8a11-a7b17f10caa1" />

기존 보이스피싱 탐지 앱은

* **GNN 기반 Batch 학습 구조**를 사용해 관계도 전체를 주기적으로 재학습
* 피해자/보호자 피드백은 **그래프에 직접 반영되지 않고**,
  가공된 GNN 데이터만 사용
* 새로운 수법이 등장했을 때

  * **즉시 반영이 어렵고**,
  * **GPU 비용·재학습 시간**이 크게 소모되는 구조

---

### 4-2. HITL-GNN 구조 설계 (내 역할 중심)

<img width="858" height="626" src="https://github.com/user-attachments/assets/43819b48-582e-4fee-98ce-a4ce3ee901c1" />

저는 기존 구조의 한계를 분석한 뒤, 다음과 같은 **HITL 기반 GNN 구조**를 설계했습니다.

* **Human-in-the-Loop(HITL)**를 도입해

  * **인간 검증 기록(피해자·보호자 피드백)**과
  * **GNN 학습 데이터**를 함께 사용
* 위험 번호·계좌·패턴에 대한 인간 판단이
  → **실시간으로 GNN 그래프에 반영**
* 전체 Batch 재학습이 아닌,
  → **일부 노드·엣지에 대한 부분 학습으로 그래프 보정**
* 결과적으로,

  * **새로운 패턴에 대한 실시간 대응**
  * **GPU 연산 비용 절감**
  * **신뢰도 높은 자가학습 구조** 구현

## 5️⃣ 데이터 파이프라인 & 서버 구조 (내 역할)

<img width="896" height="639" src="https://github.com/user-attachments/assets/5e346e61-204f-49b1-9c12-0d750f767849" />

### 🔧 제가 설계한 흐름

1. **데이터 수집**

   * 옵트인(동의) 기반 개인정보 수집
   * 통화 음성 → STT(Speech-to-Text) 변환
2. **데이터 가공**

   * 번호·계좌·관계·패턴을 **노드(Node)와 엣지(Edge)** 형태의 GNN 그래프로 변환
3. **위험 탐지**

   * GNN이 주변 관계를 분석해 **위험 점수(Risk Score) 산출**
4. **실시간 대응**

   * 기준치 초과 시: 피해자 + 보호자에게 알림 전송
   * 이때 보호자/피해자 피드백이 **HITL 데이터로 누적**
5. **그래프 보정**

   * 피드백을 기반으로 **전체 재학습 대신 부분 보정 업데이트** 수행

## 6️⃣ 음성·언어 모델 파이프라인 (사투리·지역어 대응)

<img width="1032" height="719" src="https://github.com/user-attachments/assets/3611333d-f4a8-42f9-91e3-4445094b5a0f" />

* 기존 서비스는 **표준어 중심 모델**로, 사투리·억양 인식률이 낮음
* 가디온은

  * **음향 모델(Accent/Prosody) + 언어 모델(Text)**
  * 여기에 **관계형 탐지(GNN)**를 결합한 **멀티 파이프라인 구조**를 사용
* HITL 피드백을 통해 새로운 지역어나 비표준어도 **실시간 학습 및 보정 가능**

## 7️⃣ 전체 서비스 플로우

<img width="870" height="639" src="https://github.com/user-attachments/assets/718fd0f0-8e9a-436e-a147-daa7c090f839" />

1. 통화 중 실시간 STT 변환
2. 텍스트 + 관계 정보 기반 **GNN 위험 점수 계산**
3. 기준치 초과 시,

   * 피해자 스마트폰 → 진동 + 경고 문구 표시
   * 보호자 → 긴급 문자 발송
4. 통화 종료 후

   * TTS를 이용해 **위험 내용을 음성으로 안내**
     → 1차 & 2차 예방 구조

## 8️⃣ 모델 성능 및 HITL 효과

<img width="1024" height="723" src="https://github.com/user-attachments/assets/93926fa9-917a-436b-9425-7d8639c1d606" />

연구 결과,

* **기존 GNN 단독 모델**

  * AUC: 약 0.65
  * 재현율(Recall): 약 0.6

* **HITL-GNN 적용 후**

  * AUC: 약 **+9% 향상**
  * 재현율: 약 **+8% 향상**

→ 단순 탐지를 넘어서
**신뢰도 높은 실시간 학습·예측 구조**로 발전 가능함을 확인했습니다.

## ✅ 마무리

<img width="812" height="412" src="https://github.com/user-attachments/assets/998e2da9-2b26-4650-b0fa-9cadd96e569c" />


*가디온(GUARDION)*은

* 보이스피싱에 가장 취약한 **시니어층**을 보호하고
* **AI 기술 + 보호자 연동 + 공공기관 협력**을 결합해
* 금융 취약계층 보호와 사회 안전망 확장을 지향하는 **ESG형 서비스**입니다.

> 피해를 ‘사후’에 복구하는 것이 아니라,
> **피해 이전 단계에서 고립을 깨고,
> 피해자가 스스로 금융 생활을 이어갈 수 있도록 돕는 것**이
> 가디온이 추구하는 최종 목표입니다.
